# C11 grammar

The built-in grammar of C11 (ISO/IEC 9899:2011). It extends [`lexogram:c99`](c99.md) with the changes of the syntax of C11 (Annex A of the standard); the rest, the reading of sources before preprocessing, and the choices made where C cannot be parsed without knowing which identifiers name types are those of `c99`. The rule names follow the standard and are a public contract with consumers: a change that breaks it is listed in [the changes](#changes).

```lua
local lexogram = require('lexogram')
local compiled = assert(lexogram.compile(assert(lexogram.load('lexogram:c11'))))
local result = assert(lexogram.parse(compiled, '_Static_assert(sizeof(int) >= 4, "int");'))
```

## Metadata

| Field | Value |
|---|---|
| `extends` | `lexogram:c99` |
| `lexogram` | `2026.11.15.1` |
| `name` | `c11`, the built-in grammar `lexogram:c11` (module `lexogram.grammars.c11`) |
| `version` | `2011-1`: the year of the standard and the revision of the grammar |

## keywords

The keywords of `c99`, and `_Alignas`, `_Alignof`, `_Atomic`, `_Generic`, `_Noreturn`, `_Static_assert` and `_Thread_local`.

## tokens

| Token | C11 |
|---|---|
| `character_constant` | The prefixes `u` and `U` are added to `L`: `u'a'`, `U'a'` |
| `string_literal` | The prefixes `u8`, `u` and `U` are added to `L`: `u8"a"`, `u"a"`, `U"a"` |

The other tokens are those of `c99`.

## rules

Rules added, with events:

| Rule | Pattern | Where |
|---|---|---|
| `atomic_type_specifier` | `"_Atomic" "(" type_name ")"` | A `type_specifier`: an `_Atomic` followed by `(` is this, and any other `_Atomic` is a `type_qualifier` |
| `alignment_specifier` | `"_Alignas" "(" (type_name / constant_expression) ")"` | A specifier of declarations and members; the type name is tried first, as for `sizeof` |
| `static_assert_declaration` | `"_Static_assert" "(" constant_expression "," string literals ")" ";"` | A `declaration` (external or in a block) and a `struct_declaration` |
| `alignof_expression` | `"_Alignof" "(" type_name ")"` | A term, as `sizeof_expression` |
| `generic_selection` | `"_Generic" "(" assignment_expression "," generic_association ("," generic_association)* ")"` | An operand of `postfix_expression` |
| `generic_association` | `(type_name \| "default") ":" assignment_expression` | |

Rules changed:

| Rule | C11 |
|---|---|
| `storage_class_specifier` | `_Thread_local` is added |
| `function_specifier` | `_Noreturn` is added |
| `type_qualifier` | `_Atomic` is added |
| `declaration` | `static_assert_declaration` is added |
| `struct_declaration` | `static_assert_declaration` is added, and the declarators of a member may be left out: an anonymous structure or union (`struct { int x, y; };`), which the syntax does not tell from a member of another type |

Where both an `atomic_type_specifier` and a qualifier can come, an `_Atomic` is tried as the specifier first, so that `_Atomic(T) *p;` reads `_Atomic(T)` as the type and `_Atomic int a;` reads `_Atomic` as a qualifier. The specifiers of a member may include `alignment_specifier`, as C17 corrected.

## Differences from C11

Those of [`c99`](c99.md#differences-from-c99), and:

- **_Atomic before a parenthesis**: C11 reads an `_Atomic` followed by `(` as a type specifier only; the grammar reads it as a qualifier when what follows is no type name, so `_Atomic (*p)` is accepted.
- **Members without declarators**: a member of any type may have no declarators, as the constraint that limits them to anonymous structures and unions is not syntax.

## Results on real sources

On the C sources of Lua 5.1.5 to 5.5.1 that [`c99`](c99.md#results-on-real-sources) was run on (295 files, 2026-11-19), `c11` parses 186 files (63.1%), and their event arrays cover their sources exactly. The 13 more than `c99` are headers that declare members by macros (`CommonHeader;`), which C11 reads as members without declarators; the others fail at the forms that `c99` fails at. [`c11_macro`](c_macro.md) parses 262 files, as `c99_macro`.

## Performance

Measured as for [`c99`](c99.md#performance), on the 38 files of Lua 5.4.8 that `c11` parses, concatenated and repeated to 2.24 MB (2026-11-19). Loading `c11` for the first time checks `c99` too, which it extends.

| Runtime | Load and compile | Tokenize | Parse to the event array |
|---|---|---|---|
| Lua 5.1 | 1.27 s | 5.6 MB/s | 1.2 MB/s |
| Lua 5.4 | 0.97 s | 7.8 MB/s | 1.7 MB/s |
| Lua 5.5 | 0.95 s | 7.7 MB/s | 1.7 MB/s |
| LuaJIT 2.1 | 0.54 to 0.56 s | 102 to 106 MB/s | 13 to 17 MB/s, and about 2.8 MB/s in one of five processes |
