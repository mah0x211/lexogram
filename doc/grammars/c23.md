# C23 grammar

The built-in grammar of C23 (ISO/IEC 9899:2024). It extends [`lexogram:c11`](c11.md) with the changes of the syntax of C23 (Annex A of the standard); the rest, the reading of sources before preprocessing with [the forms of macros](c_macro.md), and the choices made where C cannot be parsed without knowing which identifiers name types are those of [`c99`](c99.md) and `c11`. The rule names follow the standard, which renamed the rules of the members of structures. Like every [built-in grammar](../grammar.md#built-in-grammars), it is a sample with no promise of compatibility: copy it with `lexogram.merge` to use it, and see [the changes](#changes) for what changed.

```lua
local lexogram = require('lexogram')
local compiled = assert(lexogram.compile(assert(lexogram.load('lexogram:c23'))))
local result = assert(lexogram.parse(compiled, 'constexpr int n = 1\'000;'))
```

## Metadata

| Field | Value |
|---|---|
| `extends` | `lexogram:c11` |
| `lexogram` | `2026.11.15.1` |
| `name` | `c23`, the built-in grammar `lexogram:c23` (module `lexogram.grammars.c23`) |
| `version` | `2024-1`: the year of the standard and the revision of the grammar |

## keywords

The keywords of `c11`, and `alignas`, `alignof`, `bool`, `constexpr`, `false`, `nullptr`, `static_assert`, `thread_local`, `true`, `typeof`, `typeof_unqual`, `_BitInt`, `_Decimal32`, `_Decimal64` and `_Decimal128`. `_Alignas`, `_Alignof`, `_Bool`, `_Static_assert` and `_Thread_local` stay as their other spellings.

## tokens

| Token | C23 |
|---|---|
| `identifier` | A byte from 80 to FF is a character of a name too: the characters of Unicode that C23 allows in names (XID_Start, XID_Continue), approximated by the bytes of UTF-8, which are not checked |
| `number` | The preprocessing number has digit separators (a `'` and a digit or a letter). The constants have digit separators between digits (`1'000`, `0x1'FF`), binary integers (`0b101`), the suffixes `wb` and `uwb` of bit-precise integers (in either case and order, as `u` with `l`), and the suffixes `df`, `dd` and `dl` of decimal floating constants (`1.5df`; `2dd`, without a fraction or an exponent, is invalid) |
| `character_constant` | The prefix `u8` is added: `u8'a'` |

The symbol `::` is added, for the names of attributes. The other tokens are those of `c11`.

## rules

Rules added, with events:

| Rule | Pattern | Where |
|---|---|---|
| `attribute_specifier_sequence` | `attribute_specifier+` | Where C23 places attributes; see [Attributes](#attributes) |
| `attribute_specifier` | `"[" "[" attribute_list "]" "]"` | Two brackets, which C23 allows to be next to each other only to start or end attributes |
| `attribute_list` | `attribute? ("," attribute?)*` | |
| `attribute` | a name, or a prefix, `::` and a name, then `attribute_argument_clause?`; a keyword in a name is a name | |
| `attribute_argument_clause` | `"(" ... ")"`, any tokens with balanced parentheses, brackets and braces | |
| `attribute_declaration` | `attribute_specifier_sequence ";"` | A `declaration`: `[[fallthrough]];` |
| `member_declaration` | specifiers and qualifiers, `member_declarator_list?`, `";"`, or `static_assert_declaration` | The name of C23 for `struct_declaration`, which is removed |
| `member_declarator_list` | `member_declarator ("," member_declarator)*` | For `struct_declarator_list`, removed |
| `member_declarator` | `declarator (":" constant_expression)? \| ":" constant_expression` | For `struct_declarator`, removed |
| `typeof_specifier` | `("typeof" \| "typeof_unqual") "(" (expression / type_name) ")"` | A `type_specifier`. The expression is tried first, so that `typeof(a[0])` is the type of an element, not an array type |
| `braced_initializer` | `"{" (initializer_list ","?)? "}"` | An `initializer` and the end of a `compound_literal`; it may be empty |
| `enum_type_specifier` | `":"` and the type: integer type keywords, type names, `typeof_specifier` and qualifiers | After the name of an `enum_specifier`, or after `enum` |
| `label` | `attribute_specifier_sequence?` and `identifier ":"`, `"case" constant_expression ":"` or `"default" ":"` | A `block_item` (so a label may end a block or come before a declaration) and the start of a `labeled_statement` |
| `unlabeled_statement` | `expression_statement / attribute_specifier_sequence? (primary_block \| jump_statement)` | A `statement` and a `block_item` |
| `primary_block` | `compound_statement \| selection_statement \| iteration_statement` | |

Rules changed:

| Rule | C23 |
|---|---|
| `storage_class_specifier` | `thread_local` and `constexpr` are added; `auto` without a type specifier infers the type, which the syntax of `c99` reads already |
| `type_specifier` | `bool`, `_BitInt ( constant_expression )`, `_Decimal32`, `_Decimal64`, `_Decimal128` and `typeof_specifier` are added |
| `alignment_specifier`, `alignof_expression` | The spellings `alignas` and `alignof` are added |
| `static_assert_declaration` | The spelling `static_assert` is added, and the message may be left out |
| `postfix_expression` | `true`, `false` and `nullptr` are operands |
| `compound_literal` | Storage classes may come before the type name: `(static int[]){ 1 }` |
| `parameter_type_list` | It may be `...` alone |
| `statement`, `labeled_statement`, `block_item` | `labeled_statement` is `label statement`, and `statement` is a `labeled_statement` or an `unlabeled_statement` (a label is tried first, as two tokens do not tell the attributes of one from those of a statement) |
| `expression_statement` | It may have attributes before the expression |
| `declaration` | It may have attributes before the specifiers, and then has declarators; `attribute_declaration` is added, and tried last |
| `function_definition` | No declarations between the declarator and the body: C23 has no identifier lists, so `int f(a) int a; { }` is an error |

### Attributes

Attributes may come where C23 places them, and appertain to what they follow or precede as there:

- at the start of a `declaration`, a `function_definition`, a `member_declaration`, a `parameter_declaration`, a statement and a `label`;
- after the specifiers of a declaration, a member, a parameter and a `type_name`;
- after the identifier of a `direct_declarator`, after each `*` of a `pointer`, and after the array and function suffixes of declarators and abstract declarators;
- after `struct`, `union` and `enum` before the name or the body, and after the identifier of an `enumerator`.

Where two tokens do not tell attributes from something else, the choice is tried: an identifier in parentheses as a declarator alone before one with suffixes, an abstract declarator in parentheses before the parameters of a function suffix, and an expression statement before the other statements with attributes.

### Enumerations

An enumeration with a type and no body (`enum E : T`) followed by a name reads the name as part of the type (`enum E : T x` is `T x` as the type): C23 allows such an enumeration only in `enum E : T;`.

## Differences from C23

Those of [`c11`](c11.md#differences-from-c11), except that the identifier lists of `c99` are no more, and:

- **Names**: the bytes from 80 to FF are taken as characters of names without checking which characters of Unicode they encode.
- **Underlying types**: the type of an enumeration is not checked to be an integer type beyond the keywords allowed.
- **Nested compound literals of typeof**: `(typeof(E)){ 0 }` is tried as a cast first, which reads the type name and fails at `{`, then read again as a compound literal; nested in `E`, the time doubles with each level (about 0.4 s on Lua 5.1 fourteen levels deep). See the cost of ordered choices in [the grammar reference](../grammar.md#how-rules-are-applied).
- **Attributes**: the names of the attributes and their arguments are not checked, nor where each may appertain. A structure or union without a body may have attributes in any declaration, which the syntax of C23 allows and a constraint limits to `struct [[a]] S;`.

## Results on real sources

On the C sources of Lua 5.1.5 to 5.5.1 that [`c99`](c99.md#results-on-real-sources) was run on (295 files, 2026-11-19), `c23` parses the same 262 files as `c11`, with event arrays that cover them.

## Performance

Measured as for [`c99`](c99.md#performance), on the 51 files of Lua 5.4.8 that `c23` parses, concatenated and repeated to 2.63 MB (2026-11-20). Loading `c23` for the first time checks `c99` and `c11` too, which it extends.

| Runtime | First load and compile | Saved (`undump`) | Tokenize | Parse to the event array |
|---|---|---|---|---|
| Lua 5.1 | 2.70 s | 0.007 s | 4.7 MB/s | 1.6 MB/s |
| Lua 5.4 | 2.15 s | 0.006 s | 6.7 MB/s | 2.2 MB/s |
| Lua 5.5 | 2.12 s | 0.006 s | 6.5 MB/s | 2.2 MB/s |
| LuaJIT 2.1 | 1.15 s | 0.004 s | 90 to 93 MB/s | 11 to 19 MB/s, and about 1.3 MB/s in one of five processes |
